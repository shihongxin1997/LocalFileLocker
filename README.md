## 项目背景

本项目针对 **Windows 平台上某类本地文档加解密软件**。这类软件的典型运作方式如下：

1. 当受控程序（如 Word、WPS 等）在特定条件下把文档读入内存时，操作系统会通过 **Windows 钩子函数** 将内存中的文档数据**自动解密**；
2. 当程序保存并写回文件时，又会在落盘前通过钩子函数将数据**自动加密**。

因此，在**未安装该软件的其他系统**上，即使拿到文件也无法正常打开，或需**特别申请**才可解密外传。本项目即是在了解上述原理后，利用**原生文件读写 API** 进行**解密验证**的测试代码。

## 功能特性

- **加锁文件**：将文件追加 `.pdf` 副本后移动还原为原文件名，完成加锁伪装。
- **解锁文件**：对候选扩展名（`.pdf` / `.wps` / `.png`）逐一尝试，通过校验副本与 `.backup` 的字节差（1024 字节）确认加锁状态并还原。
- **文件夹批量处理**：递归收集文件夹下所有文件，自动跳过解锁中间产物 `.backup`。
- **图形界面**：选择源文件（夹）与输出目录，后台线程实时显示进度，UI 不冻结。
- **命令行模式**：支持 `-lock` / `-unlock` / `-output` 等参数，无参数时默认进入图形界面。
- **隐藏控制台**：图形界面模式下自动隐藏控制台窗口。
- **可选输出目录**：处理结果可输出到指定文件夹（默认输出到源对象同目录）。

## 工作原理

- **加锁**：将原文件附加 `.pdf` 扩展名生成副本，再移动回原文件名，从而隐藏真实文件类型。
- **解锁**：按候选扩展名（`.pdf` / `.wps` / `.png`）逐一尝试——
  1. 保留原扩展名并追加候选扩展名生成副本（如 `test.docx` → `test.docx.pdf`）；
  2. 读取副本字节写入 `.backup` 临时文件；
  3. 通过 PowerShell 计算副本与 `.backup` 的大小差异：
     - 差异为 **1024 字节** → 判定为已加锁，删除原文件与副本，将 `.backup` 还原；
     - 差异为 **0** → 判定文件未加锁；
     - 其他 → 判定失败并清理临时文件。

## 编译与产物

项目为 SDK 风格工程，目标框架为 `net48`，采用 C# 5 语法（`LangVersion 5`），无需额外 NuGet 包（仅引用 `System.Windows.Forms` 与 `System.Drawing`）。

使用 Visual Studio 2022 或更高版本打开 `LocalFileLocker.sln` 直接生成即可，亦可使用 `.vscode` 下提供的构建脚本。产物输出名为 `wps.exe`（见 `LocalFileLocker.csproj` 的 `AssemblyName`）。

## 使用说明

### 命令行模式

```text
LocalFileLocker.exe [选项] [文件或文件夹路径]

选项:
  -help, -h    显示帮助信息
  -gui, -g     使用图形界面
  -lock, -l    加锁文件
  -unlock, -u  解锁文件
  -output, -o  指定输出文件夹（省略时默认到文件同目录）

示例:
  LocalFileLocker.exe -g
  LocalFileLocker.exe -l C:\path\to\file.docx
  LocalFileLocker.exe -u C:\path\to\file.docx
  LocalFileLocker.exe -u C:\path\to\folder\ -o C:\output\folder
```

不指定任何参数时，程序默认进入图形界面。

### 图形界面

1. 运行程序默认打开主窗体（或通过 `-gui` / `-g` 参数进入）。
2. 在「源文件（夹）」区域点击 **文件** 或 **文件夹** 按钮选择待处理对象（支持多选）。
3. 如需指定输出目录，点击 **选择输出目录**（省略则输出到源对象同目录）。
4. 选择 **加锁** 或 **解锁** 操作类型（默认加锁）。
5. 点击 **执行**，程序逐个处理并实时显示每条处理结果与汇总信息。
